# Encore platform requirements

Guest app and organizer admin are separate routes and account contexts. Keep the guest app mobile-first. Use the supplied crimson red (#E61E32), black, white and steel-grey palette, with original Manrope typography and extracted icon geometry. Do not show demo/Figma-import narration in the customer product.

Use server sessions and enforce tenant ownership and staff roles on the server. Never restore localStorage authentication or fake payment success. AfroPay must be verified against the exact merchant provider contract before implementation; fail closed until configured. Every table has a stable unique ordering token tied to a concert. Media uploads are first-class for both event covers and menu items.

Run `npm test` (the .NET suite on PostgreSQL) and `npm run build`. Read README and PRODUCTION.md before claiming readiness. Do not include data/, passwords, recovery codes or session secrets in deliverable packages.

AfroPay checkout reference supplied September 16: blue provider header, review rows, wallet selector, Ethiopian phone field. Do not include municipal crest or city campaign affiliation. Replace the merchant strip with the tenant organization name. Wallet labels shown are Telebirr, CBE Birr, M-PESA and Awash Birr; availability has not been API-verified. Provider fees are unknown until the merchant contract is configured; never present an assumed zero fee. New workspaces default to ETB.

Architecture (September 24, replaces the September 16 two-port notes): one .NET 8 Web API (`backend/Encore.Api`) serves the guest app at `/` and the organizer admin at `/admin` on one origin; `/admin/api/*` and `/api/*` have separate routes and separate cookies (organizer, guest, platform console) — do not merge them. Layers: Controllers (HTTP only) → Services → Repositories (EF Core); business rules in `Domain/`. Guests authenticate with phone + SMS OTP through `SmsService`; never deliver or display codes outside the development console output, and never bypass OTP. Frontend: src/admin, src/guest, src/shared; icons only from src/icons.json (extracted Figma set). Payment settlement is in person ("pay at venue"); staff record payments. There is no demo mode.

Data (September 24): PostgreSQL only via DATABASE_URL — no SQLite, no file fallback. Schema changes are EF Core migrations in `Persistence/Migrations`; the baseline migration describes the tables the Python server created and changes nothing on existing databases. `npm test` starts a throwaway PostgreSQL (embedded-postgres). Uploads are stored in the database table `uploads`. Tax: `Pricing.TaxFor` implements configurable Ethiopian VAT (server-authoritative; tips untaxed); never present Encore receipts as fiscal receipts. Passwords: ASP.NET Core Identity's hasher; accounts from the Python server (scrypt) are verified and re-hashed at the next sign-in.
